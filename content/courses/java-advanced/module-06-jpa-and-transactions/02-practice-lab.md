# Practical lab: JPA, database migrations, and transactions

Persist the expense API safely under concurrent updates.

## Your challenge

Persist the expense endpoints, add a migration and a version column, then reproduce two conflicting updates.

## Environment

Extend the previous Spring API project with Spring Data JPA, PostgreSQL, and Flyway. Configure a local database and a migration before running repository operations. This fragment demonstrates the versioned model.

## Work through it

1. Predict the original example’s result without running it.
2. Reproduce it locally and explain any difference.
3. Make the requested change in small steps.
4. Check each acceptance criterion below; add a failing case before repairing a bug.

## Acceptance criteria

- [ ] A restart retains created expenses.
- [ ] Schema creation is managed by a versioned migration.
- [ ] The stale update is surfaced as a deliberate conflict response.
- [ ] A list endpoint uses a bounded query and verified fetch plan.
